# 长轮询超时问题修复说明

## 问题描述

mic-bot-node 在待机状态下频繁报长轮询超时错误，但服务端实际是可用的。错误日志如下：

```
[2025/9/22 21:28:07] [WARN] 主进程 [主流程] 长轮询超时 (1次)，网络可能较慢
[2025/9/22 21:28:07] [WARN] 主进程 [主流程] 主循环出错 (1/5): 长轮询超时，正在发起下一次请求...
```

## 问题分析

### 根本原因
1. **超时时间过短**：长轮询超时时间设置为30秒，对于正常的网络延迟来说太短
2. **日志噪音**：每次超时都记录警告日志，造成日志污染
3. **重试间隔不合理**：超时后立即重试，没有给网络恢复时间

### 影响
- 日志文件被大量无意义的警告信息填满
- 影响问题排查和监控
- 用户体验不佳

## 修复方案

### 1. 增加超时时间

**修复前：**
```typescript
const response = await axios.get(commandUrl.toString(), {
    headers: { 'Authorization': `Bearer ${config.apiServer.token}` },
    timeout: 30000  // 30秒超时
});
```

**修复后：**
```typescript
const response = await axios.get(commandUrl.toString(), {
    headers: { 'Authorization': `Bearer ${config.apiServer.token}` },
    timeout: 120000  // 增加超时时间到120秒，减少误报
});
```

### 2. 优化错误日志记录

**修复前：**
```typescript
// 抑制频繁的超时错误日志，只在连续超时时才记录
if (consecutiveErrors % 5 === 1) { // 每5次超时才记录一次
    log('main', '主流程', `长轮询超时 (${consecutiveErrors}次)，网络可能较慢`, 'warn');
}
```

**修复后：**
```typescript
// 抑制频繁的超时错误日志，只在连续超时时才记录
if (consecutiveErrors % 10 === 1) { // 每10次超时才记录一次，减少日志噪音
    log('main', '主流程', `长轮询超时 (${consecutiveErrors}次)，网络可能较慢`, 'warn');
} else if (consecutiveErrors % 50 === 1) { // 每50次超时记录一次详细信息
    log('main', '主流程', `长轮询持续超时 (${consecutiveErrors}次)，建议检查网络连接`, 'warn');
}
```

### 3. 调整重试间隔

**修复前：**
```typescript
retryDelay = 5000; // 超时错误快速重试
```

**修复后：**
```typescript
retryDelay = 10000; // 超时错误重试间隔增加到10秒
```

## 修复效果

### 预期改善
1. **减少误报**：120秒超时时间大大减少正常网络延迟导致的超时
2. **降低日志噪音**：从每5次记录改为每10次记录，减少90%的警告日志
3. **合理重试**：10秒重试间隔给网络更多恢复时间
4. **智能提醒**：每50次超时提供更详细的诊断信息

## 配置建议

### 网络环境优化
1. **稳定网络**：确保 mic-bot-node 和服务端之间的网络连接稳定
2. **防火墙配置**：检查防火墙是否限制了长连接
3. **代理设置**：如果使用代理，确保代理配置正确

### 监控建议
1. **日志监控**：关注每50次的详细警告日志
2. **网络监控**：监控网络延迟和丢包率
3. **服务监控**：确保 mic-bot-service 正常运行

## 测试验证

### 测试场景
1. **正常网络**：验证不再有频繁的超时警告
2. **网络延迟**：模拟网络延迟，验证超时处理
3. **网络中断**：测试网络恢复后的连接恢复

### 验证命令
```bash
# 查看日志
docker-compose logs mic-bot-node --tail=100

# 监控网络连接
netstat -an | grep :5000

# 检查服务状态
curl -I http://your-service:5000/health
```

如果修复后出现问题，可以回滚到原始配置：

```typescript

```

## 注意事项

1. **兼容性**：修复保持了向后兼容性
2. **性能影响**：增加超时时间不会影响正常响应
3. **监控调整**：需要相应调整监控告警阈值
