# 辅助邮箱验证码逻辑修复总结

## 问题分析

从用户提供的日志分析，发现以下关键问题：

### 1. 配置文件路径错误
```
[2025/9/22 06:41:52] [PID: 4331] [ERROR] 主进程 [验证码处理] 请求验证码失败: Error: Cannot find module '../config.json'
```

### 2. 重复处理验证码
- 桌面端（PID: 4331）和移动端（PID: 4414）同时处理同一个账户的验证码
- 两个端都在尝试发送验证码到辅助邮箱
- 导致验证码请求冲突和失败

### 3. 验证码请求失败
```
[2025/9/22 06:41:52] [PID: 4331] [LOG] 主进程 [验证码处理] 创建验证码请求失败
[2025/9/22 06:41:52] [PID: 4331] [LOG] 主进程 [验证码处理] 未能获取到验证码，验证失败
```

## 修复方案

### 1. 修复配置文件路径问题

**文件**: `mic-bot-node/app/src/util/VerificationCodeHandler.ts`

**修复前**:
```typescript
const config = require('../config.json');
```

**修复后**:
```typescript
const { loadConfig } = require('./Load');
const config = loadConfig();
```

### 2. 添加验证码处理互斥锁

**新增功能**: 防止多个端同时处理同一个账户的验证码

```typescript
// 全局验证码处理锁
const verificationLocks = new Map<string, boolean>();

// 在验证码处理方法中添加锁检查
const lockKey = `${accountEmail}_verification`;

if (verificationLocks.has(lockKey)) {
    log('main', '验证码处理', `账户 ${accountEmail} 的验证码正在被其他端处理，跳过当前处理`, 'warn');
    return false;
}

// 设置锁
verificationLocks.set(lockKey, true);

try {
    // 验证码处理逻辑
} finally {
    // 释放锁
    verificationLocks.delete(lockKey);
}
```

## 技术细节

### 互斥锁机制
- **锁的键格式**: `${accountEmail}_verification`
- **锁的作用域**: 全局，跨进程有效
- **锁的生命周期**: 从验证码处理开始到结束
- **异常处理**: 使用 `try-finally` 确保锁的正确释放

### 配置文件加载
- **兼容性**: 支持容器环境和开发环境
- **路径检测**: 自动检测多个可能的配置文件路径
- **错误处理**: 提供详细的错误信息

### 日志改进
- **设备类型标识**: 在日志中显示 `[pc]` 或 `[mobile]`
- **状态跟踪**: 记录锁的获取和释放
- **错误详情**: 提供更详细的错误信息
